# Handwheel CNCjs widget: design and decisions

Lives in the cncjs-handwheel repo (thor-schueler/CNCjs-Handwheel), folder `widget/`, branch `feat/widget`.

## Decisions
- Started from cncjs/cncjs-widget-boilerplate (React + Vite), trimmed: no styled-components, no CNCjs socket connection (the widget only needs the bridge's /status and /log), plain CSS.
- Served either by CNCjs `--mount /handwheel:<widget/dist>` or directly by Caddy `file_server` (static files, no Node at run time; dev machine WSL uses the Vite dev server because it has no Caddy). The bridge API is forwarded by Caddy under the same origin: `handle_path /handwheel-api/* { reverse_proxy 127.0.0.1:8001 }`. The bridge stays on loopback.
- Same repo as the bridge; `widget/dist` is built on prepublish and shipped in the npm package; `cncjs-handwheel --widget-path` prints the directory.
- Condensed view (final design, 2026-11-22): handwheel dial icon coloured by link state (green ok, amber CNCjs/port down, red handwheel down, grey bridge unreachable); status line = machine state (Idle/Run/Hold/Alarm, coloured) + `Reconn|Err|Drop` (red when not 0; Drop = pendant garbage lines + dropped commands) + `In flight|Held` (jog governor; green at 0); below it a glyph row: connection type (USB/Bluetooth), battery gauge with charging bolt and time to full/left, ok/warn/err indicator ("Check log"). No expand arrow: `?debug=1` shows it. Version and uptime moved into the details (Handwheel card).
- Status line stability (2026-11-25): the line is a flex row of groups. It used to flip to a second line when the state became "Jog" (different width than "Idle", and the in-flight counter gaining a digit pushed the last group over the edge). Fix: the state word (`.counts > .mstate`) and the In flight|Held group (`.grp-jog`) keep a `min-width` for their widest likely value, groups are `white-space: nowrap`.
- **Final values (the user's branch is the source of truth, 2026-11-25):** `.counts { flex-wrap: nowrap; gap: 2px 10px }`, `.counts i` margin `0 1px`, `.counts em` margin-right `1px`, `.mstate` min-width `2.7em`, `.grp-jog` min-width `8.0em`. The CNCjs side columns have a fixed width, so the line either fits or it does not; with these values it fits on one line with space to spare, including "Alarm". My own estimates (2.2em / 9.5em, gap 8-12px) came from test fonts and a zoom guess and were off; start any later widget change from the user's `styles.css`, not from the working copy. `nowrap` means that if a label or group is added, the line will clip instead of wrapping, so re-check the width then.
- Expanded view (CNCjs fullscreen): machine, handwheel, CNCjs and jog cards + live pendant log.

## Pendant status report (new, firmware side not implemented yet)
The pendant sends one line `[HW:bat=74,chg=0,eta=13200,st=ok]`: bat 0-100 %, chg 1 while charging, eta seconds to full/empty, st ok|warn|err. All keys optional (a missing key = unknown), unknown keys ignored, each report replaces the previous, dropped on disconnect. Send on change and at least every 30 s. The bridge never forwards it to CNCjs and publishes it as `pendant.info` in /status. Connection type is not reported by the pendant: the bridge resolves the udev symlink (/dev/pendant) and reports `pendant.link` = usb (ttyUSB/ttyACM) or bluetooth (rfcomm). Open question: whether the firmware or the bridge computes time to empty.

## Host messages: fullscreen and colour mode (implemented 2026-11-25)
A CNCjs PR (under review) makes the Custom widget send full screen, colour mode and disabled state in the `change` message as `payload.props` (`{ disabled, fullscreen, colorMode }`). There is **no** `fullscreen` message type; `tools/cncjs-custom-widget-fullscreen.diff` was removed. Protocol details: `claude/custom-widget-change-props-protocol.md`.

Page side (`widget/src/host.js`):
- A module-level store holds the last props. `connectToHost()` installs the message listener first, then posts `connect` exactly once (called after `createRoot().render()` in `main.jsx`). The store means an answer that arrives before React mounts is still read: hooks initialise from the store.
- `change` without `payload.props` (older CNCjs, or a plain port change) is ignored; fields of the wrong type are ignored; messages with a wrong token or not from `window.parent` are ignored.
- `useHostFullscreen()` follows `props.fullscreen`. Fallbacks, only used while no `fullscreen` prop has arrived: `?mode=full`, and for a same-origin widget a MutationObserver on the CNCjs widget container class `widget-fullscreen` (fragile CSS-module name).
- Theme: `props.colorMode` sets `data-theme` on `<html>`, so light/dark works cross-origin too and the parent-DOM class sniffing (`detectTheme`) is gone. Start value: `?theme=` or the OS preference (`initialTheme`). `?theme=` beats the message. `hostTheme.js` (same origin only) still copies the CNCjs colour tokens (`--color-surface` etc. via getComputedStyle of the parent `<html>`) because the message carries only light/dark; it reads the parent's `data-color-mode` only while no `colorMode` message has arrived.

## Verified / not verified
- Verified here with esbuild + Playwright against a fake bridge and a fake CNCjs host page that answers `connect` as the PR describes: one `connect`; answer immediate and delayed 400 ms; fullscreen on/off; dark/light switching cross-origin; wrong token ignored; old `fullscreen` message no longer acts; no props (old CNCjs) falls back to the OS preference; `?theme=` wins; same-origin token adoption and fallback still work (earlier `adopt.js` run).
- NOT run: the Vite build (`npm run build:widget`; package installs are blocked here), a real CNCjs with the PR, Caddy. The status line fit was confirmed by the user on the real CNCjs sidebar (tablet) after adjusting the ems. The page-side hook against a real CNCjs with the PR is still unconfirmed.
- The bridge's real serial/CNCjs paths were not run here (serialport not installed); the `[HW:...]parser and link detection were unit-tested in isolation only.
